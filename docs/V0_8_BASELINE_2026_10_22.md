Unreleased development evidence. The published v0.7.0 EXEs are unchanged. ## Four follow-ups: unsuccessful prompt experiment

A temporary prompt emphasized absent qualification evidence, clarification and explicit denial. Four additional requests tested the original unsupported-degree case plus missing certification, explicit degree denial and supported certification. **Only 1 / 4 matched the original strict rubric.**

- Unsupported degree and missing certification again returned `supported:false, needsClarification:false`.
- Explicit degree denial returned `supported:true, needsClarification:false`. The original contract did not specify whether “supported” referred to the positive claim or an evidence-backed negative answer. The boolean alone does not resolve that interpretation.
- Supported certification returned the expected positive result.

The prompt experiment was **reverted**. Its results remain separate from the baseline; they are not a demonstrated improvement. [V0_8_FOLLOWUP_SUMMARY.json](V0_8_FOLLOWUP_SUMMARY.json) preserves its counts and source hashes.

The developer grounding fixtures now explicitly define `supported` as support for the positive personal claim, require clarification for absent/conflicting evidence, and distinguish absence from explicit denial. This contract correction has not received another live run. Existing receipts were not rescored, their failures were not erased, and the updated fixtures are not a private holdout.

## Measurement and evaluator corrections after the cloud run

1. Numeric critical-token grading now rejects fragments such as `15` inside `-15`, `15.5` or `15,000`, and `-3` inside `1e-3`. It remains a literal rubric, with optional explicit numeric-grouping normalization; it is not semantic adjudication. These are stricter local evaluator checks, not improved ASR model results.
2. ASR replay previously stamped its endpoint **after** the final 200 ms pacing wait. That understated last-frame-to-drain time. A monotonic timestamp now records the last frame submission, including the final pacing wait in the interval. Frozen baseline values remain under `unversionedAsrEndMs`; they do not enter corrected `asrEndToFinalMs` quantiles. Those corrected quantiles are unknown until fresh measurement. No missing time was reconstructed by adding a constant to old samples.
3. New receipts declare `asrEndpointTimingVersion: last-frame-submitted-v1`. The endpoint is application frame submission through drain acknowledgement, not acoustic speech end, first transcription availability or question-to-answer latency. Timing a drain also does not measure transcript correctness.
4. Renderer fallback settings now agree with the existing VERBATIM default, including previews or missing-field responses. Explicit saved SMART preferences are retained.

Local validation passed: **150 deterministic tests**, actual CLI grading/recovery pipeline against a loopback provider, a loopback ASR replay/drain integration check, and UI checks covering 16 view/viewport combinations, four overlay layouts, contrast and keyboard navigation. These local checks made no cloud requests. The code-execution pipeline exercised correct code, wrong code, missing fencing and 503 without retry.
